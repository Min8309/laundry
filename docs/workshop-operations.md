# 글쓰기 작업실 · 구현 범위와 운영 결정

## 이번 작업본

GitHub `main` 기준 `fc89605` 위에 만든 로컬 프로토타입입니다. `dist/workshop.html`과 메인 메뉴 링크를 추가했습니다. 원문·사진·음원·기존 음악 로직·배포 설정은 수정하지 않았습니다. 작업실은 한국어 전용이며 영어 번역/생성 기능은 없습니다. 실제 사이트는 버전 20의 소유자 전용 비공개 상태를 유지합니다. 사용자의 후속 요청으로 GitHub에 전달하는 작업본이며, 사이트 배포는 별도 승인 전 진행하지 않습니다.

작동하는 기능:
- 옷, 키워드, 소재/짧은 글, 제목과 본문 직접 작성 및 수정
- 공백·줄바꿈 포함 글자 수, 3,000~5,000자 권장 분량 안내 (본문 입력 상한 20,000 UTF-16 코드 단위)
- 독자 화면 미리보기. 입력을 HTML로 실행하지 않고 `textContent`로 표시
- 나만 간직/익명 공개 투고 준비 의향 선택. 실제 투고·공개하지 않음
- 명시적으로 누를 때만 브라우저 localStorage에 원고 한 편 저장, 다음 방문 시 복원
- 제목·본문·소재·공개 의향이 담긴 UTF-8 TXT 다운로드
- 저장 오류 안내, 저장하지 않은 수정이 있을 때 페이지 이탈 경고 (브라우저가 지원하는 범위)

저장은 계정 보관함이나 암호화 저장이 아닙니다. 공유 기기 사용자나 같은 출처의 스크립트가 읽을 수 있습니다. 브라우저 데이터 삭제 시 사라집니다. 기존 저장된 한 편을 다시 저장하면 교체하므로 중요한 버전은 TXT로 내려받아 보관해야 합니다. JSON 가져오기·여러 작품 관리·복원 이력은 아직 없습니다. 저장 형식이 잘못됐으면 자동 덮어쓰지 않고 안내하며, 사용자가 저장 버튼을 누를 때만 교체합니다. 외부 웹폰트는 기존 스타일시트에서 로드될 수 있지만 원고·폼 데이터는 전송하지 않습니다.

## 사용자 결정과 미확정 항목

결정한 방향은 가입 계정별 최초 소설 1편 무료, 이후 유료, AI 횟수 제한, 공개 투고 선택 시 책 표지 무료 생성입니다. UI는 이를 예정 정책으로 표시하며 잔여 횟수나 가짜 결제 결과를 만들지 않습니다. 실제 가격·AI 호출 세부 횟수·무료 1편의 차감 시점·실패 환급·수정의 과금 단위·무료 표지 재생성 횟수는 미확정입니다. 원고 생성, 다듬기, 가입, 결제, 이미지 생성, 투고는 비활성 버튼입니다.

## 실제 서비스 전 필요한 서버 설계

1. **계정과 원고 소유권**: 서버에서 인증한 계정 ID를 원고 소유자에 연결하고, 조회·수정·삭제 권한을 모든 요청에서 확인합니다. 공개 작품에는 실명/계정 ID를 내보내지 않습니다. 익명은 독자에게만 적용되고 운영자는 소유권·신고 대응을 위해 권한 범위에서 연결을 관리합니다. 공개 동의와 원고 권리 확인을 별도로 받고 철회/삭제 방법을 마련합니다.
2. **무료 1회와 결제**: 브라우저 저장값으로 무료 횟수를 판단하지 않습니다. 계정별 지급·예약·소진 기록을 서버 트랜잭션과 고유 제약으로 관리하여 중복 클릭·동시 요청·재시도에 한 번만 차감합니다. 다중 계정 남용은 별도 가입 검증·요청 제한 정책이 필요하며 ‘계정당 1회’만으로 차단된다고 보장할 수 없습니다. 결제는 검증된 공급자 웹훅의 서명·금액·통화·주문 소유권을 확인하고 중복 이벤트를 처리합니다. 성공 화면만으로 이용권을 지급하지 않습니다.
3. **AI 비밀과 예산**: API 키는 서버 비밀 저장소에 두고 HTML/JS/GitHub에 넣지 않습니다. 모델 허용 목록, 입력·출력 토큰 상한, 계정별/일별 요청 제한, 동시 실행 수, 작업 제한시간, 재시도 횟수, 서비스 전체 일/월 비용 상한과 차단 스위치를 둡니다. 예약→성공→소진 및 실패 시 예약 해제를 구분합니다. 프롬프트나 원고의 지시가 비용 제한·검수 규칙을 바꾸지 못하게 합니다.
4. **표지와 투고**: 공개 투고 선택만으로 제한 없는 이미지 API를 호출하지 않습니다. 원고/계정 소유권과 표지 이용 조건을 서버에서 검증하고 작품별 한도·재생성 규칙을 정합니다. 생성 이미지를 비공개 저장한 뒤 검수와 공개 동의를 거쳐 게시합니다. 공개 철회 시 원고와 표지 처리 규칙도 필요합니다.
5. **검수·신고**: 접수→검수 대기→승인/보완 요청→공개 상태를 분리합니다. 개인 정보, 타인 권리, 유해 콘텐츠를 점검하고 신고·삭제 요청·차단·이의제기 경로와 운영 담당자를 정합니다. 관리 화면은 일반 독자와 권한을 분리하고 변경 이력을 남깁니다. 저장 XSS를 막기 위해 원고는 텍스트로 렌더링하거나 검증된 정화 과정을 사용합니다.
6. **백업·운영**: 데이터베이스·원고 버전·표지 객체 저장소를 백업하고 복원 시험, 보존/삭제 주기, 장애 알림, 접근 로그, 관리자 최소 권한을 마련합니다. 로그에 원고 전문·키·결제정보를 기본 수집하지 않습니다. 운영/개발 환경과 비밀을 분리합니다.

참고 자료는 전달받은 ‘Oracle VM·WordPress·Cloudflare Tunnel 운영 문서’ 요약만 활용했습니다. 원문이나 글 생성 구현을 확보한 것은 아닙니다. 백업·관리·보안 관점만 설계에 반영했으며, 기존 사이트를 해당 환경으로 옮기거나 WordPress/Tunnel을 설치하지 않았습니다.

## 원가와 출시 전 결정

실제 모델·가격·호출 횟수가 정해지지 않아 숫자 원가나 판매가를 확정하지 않았습니다. 작품당 예상 변동비는 **입력/출력 토큰 비용 + 다듬기·실패 재시도 비용 + 무료 표지 생성 비용 + 저장/전송비 + 결제 수수료**입니다. 검수·신고 대응 시간과 고정 서버비도 별도로 반영해야 합니다. 표지를 무료 제공해도 운영 원가는 발생합니다.

출시 전에는 (1) 텍스트·이미지 공급자와 실제 단가/보존 정책, (2) 작품별 생성·수정·재시도·표지 횟수, (3) 무료 차감/실패 환급 기준, (4) 판매가·판매 단위·환불 조건, (5) 전체 예산 상한과 경보, (6) 공개 검수 담당자/처리 기간, (7) 데이터 삭제·백업 보존 기간을 결정해야 합니다. 이 페이지 제작으로 계정·결제·AI 서비스가 준비된 것은 아닙니다.
